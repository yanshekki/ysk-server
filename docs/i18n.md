# Internationalization (i18n)

> Language: English | [中文](./i18n-ZH.md)

## Supported languages

| Code | Notes |
|------|--------|
| **zh-HK** | Default UI |
| **zh-CN** | Simplified Chinese |
| **en** | English |

`zh-TW` / bare `zh` normalize to `zh-HK`.

## Source of truth

```
packages/shared/locales/{zh-HK,zh-CN,en}/
```

Web: `t()` via react-i18next. Backend: `tl()` / `t(locale, key)`. CLI: `--locale` / `YSK_LOCALE`.

## Developer workflow

1. Edit all three locale JSON namespaces in parallel.  
2. Prefer semantic keys; write zh-HK first, then zh-CN and en.  
3. `pnpm i18n:rebuild`  
4. `pnpm i18n:check-keys && pnpm i18n:check-glossary && pnpm i18n:check-ui && pnpm i18n:check-api`

## Gates

| Script | Role |
|--------|------|
| `i18n:check-keys` | Key sets match across locales |
| `i18n:check-ui` | No hardcoded CJK in web sources |
| `i18n:check-api` | No hardcoded CJK operator strings in core/server |
| `i18n:check-glossary` | zh-HK forbidden wording (e.g. 軟體→軟件) |

## Request locale

| Source | Priority |
|--------|----------|
| HTTP `Accept-Language` | Primary for API messages |
| `?locale=` | Override |
| CLI `--locale` / env | CLI session |
